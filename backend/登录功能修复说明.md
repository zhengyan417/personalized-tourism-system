# 登录功能修复说明

## 问题根源

登录一直显示"密码错误"的原因有三个：

### 1. **数据库字段名不匹配**
   - 数据库schema中定义的是 `user_id` 和 `password`
   - 代码中使用的是 `id` 和 `password_hash`
   - **修复**：统一使用数据库schema中的字段名

### 2. **密码哈希格式复杂**
   - 原使用 `werkzeug.security` 的 scrypt 哈希（162字符）
   - 验证逻辑复杂，容易出错
   - **修复**：改用简单的 SHA256 哈希（64字符）

### 3. **DictCursor 返回格式问题**
   - `pymysql.cursors.DictCursor` 返回 dict，不是 tuple
   - 直接解包 dict 会得到键名，不是值
   - **修复**：在 `auth_service.get_user_by_username()` 中将 dict 转换为 tuple

## 修复的文件

1. **`backend/app/services/auth_service.py`**
   - 移除 werkzeug.security 依赖
   - 使用 `hashlib.sha256()` 进行密码哈希
   - 修复 `get_user_by_username()` 返回格式（dict → tuple）

2. **`backend/app/routes/auth.py`**
   - 更新字段名：`id` → `user_id`, `password_hash` → `password`

3. **数据库密码转换**
   - 运行 `convert_passwords.py` 将所有用户密码转换为 SHA256 格式

## 注意事项

1. **密码哈希方式已简化**
   - 从 scrypt (162字符) 改为 SHA256 (64字符)
   - 新注册的用户会自动使用 SHA256 哈希
   - 所有现有用户密码已转换为 SHA256

2. **数据库字段**
   - 确保使用 `user_id` 和 `password` 字段名
   - 不要使用 `id` 或 `password_hash`

3. **Session 管理**
   - 登录成功后会设置 Flask session
   - session 数据存储在服务器端
   - 需要配置 `SECRET_KEY` 以启用 session
